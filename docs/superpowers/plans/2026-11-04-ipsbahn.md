# IPSBahn Bahntafel – Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** IP-Symcon-Modul „Bahntafel“, das für einen Heimatbahnhof Abfahrt und Ankunft aus der DB Timetables API mit Echtzeitdaten im WebFront (`~HTMLBox`) und in der Tile-Visu zeigt.

**Architecture:** Eine Bibliothek mit einem Gerätemodul (`Bahntafel/`). IPS-freie Klassen in `libs/` übernehmen Abruf und Parsing (`TimetablesClient`), Gattung und Badge (`TrainBadge`), Tafellogik (`BoardBuilder`) und HTML (`BoardHtml`). `module.php` verbindet sie mit Eigenschaften, Attributen, Variablen, Timern und dem Formular. Aufbau und Testweise folgen `../symcon-doorstation`.

**Tech Stack:** PHP 8.3 (`../tools/php/php`), IP-Symcon 9 Modul-SDK, DOMDocument für XML, curl, Vanilla-JS/CSS in `module.html`. Kein Composer, kein PHPUnit, eigener Runner `tests/run.php`.

**Spec:** `docs/superpowers/specs/2026-11-04-ipsbahn-design.md`. Vor jeder Aufgabe lesen.

## Global Constraints

- `library.json`: name `IPSBahn`, author `captmajac`, url `https://github.com/captmajac/IPSBahn`, `compatibility.version` `9.0`, version `1.0`.
- `module.json`: name `Bahntafel`, type 3, vendor `IPSBahn`, prefix `BAHN`, aliases `["Bahntafel", "DB Bahntafel"]`. GUIDs neu erzeugen (`uuidgen`).
- API-Basis `https://apis.deutschebahn.com/db-api-marketplace/apis/timetables/v1/`, Header `DB-Client-Id`, `DB-Api-Key`, `Accept: application/xml`.
- Zugangsdaten nie in Code, Tests, Fixtures, Doku oder Commits. Fixtures enthalten nur API-Antworten.
- Code, Kommentare und Formular-Texte auf Englisch, deutsche Übersetzung in `locale.json` (wie Doorstation). Commit-Messages englisch, kurz, Präfix `Bahntafel:` bzw. `Libs:` / `Tests:`.
- Keine öffentlichen Methoden außer `Create`, `ApplyChanges`, `RequestAction`, `GetConfigurationForm`, `GetVisualizationTile` (Konventionstest). Timer und Formular-Buttons rufen `IPS_RequestAction($_IPS['TARGET'] bzw. $id, '<Ident>', …)`.
- Kein `IPS_LogMessage`, nur `$this->LogMessage(…, KL_ERROR|KL_MESSAGE)`. Kein `IPS_SetProperty` / `IPS_ApplyChanges` im Modul.
- Feste Statusfarben: Grün `#43A047`, Orange `#FB8C00`, Rot `#E53935`, Grau = Textfarbe mit 50 % Deckkraft.
- Standardwerte: Intervall 60 min (15–240), Zeilen 10 (1–20), Wegezeit 0, Toleranz 4, andere Züge „ausblenden“, Bus aus, alle anderen Gattungen an. Sperre beim Umschalten 300 s, Neuberechnung alle 60 s.
- Alle Ausgaben von API-Texten werden HTML-escaped (`htmlspecialchars` bzw. `textContent` in JS).

## Review Focus

1. **Mitternacht:** Um 23:xx muss `plan` für `yymmdd` des nächsten Tages und Stunde `00` abgerufen werden, Zeiten über Mitternacht werden korrekt sortiert. Test in Task 2 und Task 4.
2. **Stop ohne `dp` bzw. `ar`:** An Start- und Endbahnhöfen fehlt eines von beiden. Solche Fahrten dürfen nur in der jeweils anderen Tafel erscheinen, ohne Warnung oder Fehler. Test in Task 2 und Task 4.
3. **Änderung ohne Plan-Eintrag:** `fchg` enthält Stops, die nicht in den geladenen `plan`-Stunden liegen. Sie werden ignoriert und erzeugen keine Fahrt mit leeren Feldern. Test in Task 2.
4. **Sonderzeichen in API-Texten:** Bahnhofsnamen wie „Großstadt Hbf“ oder „Löwenstadt Hbf“ sind harmlos, Meldungen mit `<`, `&`, `'` dürfen aber weder HTML noch Tile brechen. Test in Task 5 und Task 7.
5. **Heimatbahnhof noch nie abgerufen / API von Anfang an kaputt:** Tafel und Tile zeigen einen Hinweis statt leer oder Exception, `Trips` ist `[]`. Test in Task 6.

### Task 2: TimetablesClient

**Files:**
- Create: `libs/TimetablesClient.php`
- Test: `tests/test_client.php`

**Interfaces:**
- Produces:
  - `new TimetablesClient(string $clientId, string $apiKey, ?callable $http = null)`. `$http(string $url, array $headers): array{status:int, body:string}`, Standard ist curl mit 10 s Timeout.
  - `searchStations(string $pattern): array` → `[['eva' => '8099001', 'name' => 'WohnortBahnhof'], …]`
  - `fetchTrips(string $eva, int $now): array{trips: array, realtime: bool}`. Wirft `TimetablesAuthException` bei 401/403 und `TimetablesException` bei anderen Fehlern von `plan`. Ein Fehler bei `fchg` gibt `realtime: false` und die Solldaten zurück.
  - Trip-Array (in späteren Tasks verbindlich):
    ```
    ['id' => string, 'line' => string, 'category' => string, 'number' => string,
     'dep' => null|Stop, 'arr' => null|Stop, 'messages' => string[]]
    Stop = ['planned' => int, 'changed' => ?int, 'platform' => string,
            'changedPlatform' => ?string, 'path' => string[], 'cancelled' => bool]
    ```
    `line` = `dp@l` bzw. `ar@l` (leer, wenn nicht vorhanden), `category` = `tl@c`, `number` = `tl@n`. Bei `dep` stehen in `path` die *folgenden*, bei `arr` die *vorherigen* Bahnhöfe, aus `ppth` per `|` getrennt. Zeiten sind Unix-Timestamps aus `yymmddHHii` in `Europe/Berlin`.
  - Auch statisch: `TimetablesClient::parsePlan(string $xml): array` (Trips ohne Änderungen), `parseChanges(string $xml): array` (id → Änderungsfelder + messages), `merge(array $trips, array $changes): array`.

- [ ] **Step 1: Failing tests** in `tests/test_client.php`:
  - `parsePlan(plan_wohnort_18.xml)`: Anzahl Trips = Anzahl `<s>` in der Datei. Ein bekannter Trip aus der Fixture (in der README notiert) hat die erwartete `line`, `planned` (`mktime(…)` aus dem pt-Wert), `platform` und als letzte `dep.path`-Station die erwartete Station.
  - Ein Stop nur mit `ar` (Endbahnhof) hat `dep === null`, einer nur mit `dp` hat `arr === null`.
  - `merge` + `parseChanges(fchg_…)`: Der Trip mit `ct` hat `changed` gesetzt, der mit `cp` hat `changedPlatform`, der mit `cs="c"` hat `cancelled === true`, Meldungen landen in `messages`. `fchg`-IDs ohne Plan-Trip erzeugen keinen neuen Trip (Anzahl unverändert).
  - `fetchTrips('8099001', 2026-11-04 23:30)` mit Fake-`$http` ruft genau die URLs `plan/8099001/261104/23`, `plan/8099001/261105/00` und `fchg/8099001` auf, mit beiden Headern.
  - Fake-`$http` liefert 401 → `TimetablesAuthException`. `plan` liefert 500 → `TimetablesException`. `fchg` liefert 500 → `realtime === false`, Trips vorhanden.
  - `searchStations` über `station_wohnort.xml` → enthält `['eva' => '8099001', 'name' => 'WohnortBahnhof']`.
- [ ] **Step 2:** Laufen lassen. Erwartet: FAIL (`Class "TimetablesClient" not found`).
- [ ] **Step 3: Implementieren.** DOMDocument mit `libxml_use_internal_errors(true)`, kaputtes XML → `TimetablesException`. **Meldungen:** Text aus dem Attribut, das die Fixture tatsächlich liefert, laut README Task 1. Haben die Meldungen nur Codes (`c`), dann `libs/MessageCodes.php` mit `MessageCodes::text(int $code): ?string` anlegen. Die Tabelle wird aus dem Anhang „Codes“ der DB-Timetables-API-Doku übernommen, unbekannte Codes werden weggelassen. Doppelte Meldungen je Trip entfernen.
